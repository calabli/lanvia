# Lanvia

**简体中文** | [English](README.en.md)

局域网内多台设备（Mac / Windows / Linux / iPhone / iPad / 安卓）即时共享剪贴板和文件。

- **电脑**：运行一个单文件程序，自动监听系统剪贴板，收到的内容直接写入剪贴板，⌘V / Ctrl+V 即可粘贴。
- **手机 / 平板**：不用安装，相机扫码后用浏览器打开（可“添加到主屏幕”）。
- **多台电脑**：使用同一个配对码后通过 UDP 广播自动发现并互相同步，不需要服务器，也不需要外网。

## 下载与运行

**桌面客户端（推荐）**：Mac 解压 `Lanvia-macos.zip` 后把 `Lanvia.app` 拖进“应用程序”；Windows 直接运行 `Lanvia-windows-amd64.exe`。它常驻在菜单栏 / 托盘，不需要浏览器：

| 操作 | 作用 |
| --- | --- |
| 点托盘图标 | 弹出快捷面板：直接打字搜索，↑↓ 选择，回车写入剪贴板并收起，Esc 收起 |
| 右键托盘图标 | 最近 6 条内容一键复制（文件则保存并在访达/资源管理器中显示）、收藏、主动复制 / 主动粘贴开关、发送当前剪贴板、暂停同步、开机启动、检查更新、退出 |
| 面板里按 **空格** 或 **⌘Y** | 悬浮预览窗口：长内容完整查看，回车复制全部，选中一段 ⌘C 只复制这段 |
| 面板里按 **⌘E**，或预览里点“编辑” | 修改内容，⌘S 保存为新版本，同步到所有设备 |
| 预览里点时钟按钮 | 历史版本：谁在什么时候改了什么，逐行对比，可复制或恢复任意版本 |
| 条目上的计时器按钮 | 这一条的保留时长：1 小时 / 1 天 / 7 天 / 30 天后删除、永久保留，同步到所有设备 |
| 条目上的星标 | 收藏为常用片段，可以命名（例如“家里 WiFi”）；不会过期，托盘菜单的“收藏”里点一下就复制 |
| 顶栏的 Aa 按钮 | 拖动滑块调整全部文字大小（80%–160%），每台设备各自保存；桌面版也可以用 ⌘/Ctrl 加 + − 0 |
| 输入框旁的“新建清单” | 共享清单（购物清单、出门要带的东西）：直接在卡片上勾选、添加、修改；输入框里有多行文字时一键转成清单 |
| 条目上的标签按钮 | 给内容加标签（例如 #工作 #快递），同步到所有设备；列表上方的标签栏点一下只看这个标签，搜索框里输入 `#工作` 也能按标签筛选 |
| 条目上的评论按钮 | 给内容加评论（例如“改到四点了”），同步到所有设备，打开着的预览里实时出现 |
| 搜索框 | 空格分隔多个关键词同时匹配；找不到时模糊匹配（`wfmm` 能找到“WiFi 密码”）；可按类型、设备、时间筛选 |
| 拖入文件夹 / “添加文件夹” | 在本机打包成 zip 后发送 |
| 托盘菜单 → 打开主窗口 | 配对二维码、设置（语言、发送模式、历史保留时间、自动下载文件、文件占用上限、加密、手动添加设备）、完整历史 |

**找不到对方时**：配对码相同但一直不显示对方（路由器屏蔽了广播、不在同一网段等），在设置的“手动添加设备”里填对方的 IP 即可，只需在一台电脑上添加。路由器开了 AP 隔离时设备之间完全不通，手动添加也无法解决。

预览窗口会自动识别 JSON、JavaScript、Go、Python、Shell、SQL、HTML、CSS、YAML 并高亮，JSON 可以一键格式化。界面支持中文和 English，默认跟随系统语言。

**主动复制 / 主动粘贴**：两个独立的开关。主动复制开着时，在电脑上复制即发送；关掉后复制不发送，需要时从托盘菜单或页面上的“发送剪贴板”手动发送。主动粘贴开着时，其他设备发来的文字自动放进本机剪贴板，直接粘贴；关掉后只出现在列表里。在访达里复制的文件、密码管理器复制的密码都不会自动发送，文件请拖进窗口。

**图片**：在 Mac、Windows 上复制或截取的图片（只有图片、没有文字时）会作为图片文件发送，规则和文字一样（主动复制、暂停、应用黑名单都适用）；开着主动粘贴时，其他设备发来的图片（20 MB 以内）也会放进本机剪贴板，直接粘贴。Linux 暂不支持图片。

第一次启动会自动打开主窗口，方便手机扫码配对。关闭窗口不会退出，Lanvia 会继续在后台同步。

- **系统通知**：其他设备发来内容时弹出通知，文字可以直接点“复制”，点通知打开预览；有 Lanvia 窗口在前台时不弹。
- **暂停同步**：托盘里暂停 15 分钟 / 1 小时 / 直到手动恢复，期间本机复制的不发送、收到的不写入剪贴板。
- **应用黑名单**：设置里添加应用（或从“最近复制来源”里点选），在这些应用里复制的内容不会发送。
- **自动更新**：启动后和每 6 小时检查一次 GitHub 上的新版本，托盘里一键更新（按 SHA256 校验后替换并重启）。仓库需要是公开的才能检查。

**命令行版**：适合服务器、Linux 或不想要界面的场景。

```bash
go run ./cmd/lanvia
```

终端会打印配对码、局域网地址和二维码；浏览器打开 `http://localhost:8686` 是同样的管理页面。命令行版和桌面版不要同时运行，它们共用配置和端口。

常用参数：

| 参数 | 说明 |
| --- | --- |
| `--join XXXXX-XXXXX` | 使用另一台电脑的配对码，加入它的空间（也可以在管理页面里操作） |
| `--peer 192.168.1.20:8686` | 手动指定对端（仅本次运行），路由器屏蔽广播或跨网段时使用 |
| `--no-discovery` | 不使用局域网广播，只连接手动添加的设备 |
| `--name 书房电脑` | 设备名 |
| `--port 8686` | HTTP 端口（广播固定使用 UDP 8687） |
| `--no-watch` | 不监听本机剪贴板 |
| `--lang en` | 终端输出和日志的语言（`zh` / `en`），默认跟随系统 |
| `--data DIR` | 数据目录，默认在系统配置目录下的 `Lanvia/` |

## 打包

在 Mac 上执行，产物在 `dist/`：

```bash
scripts/build.sh
```

- `Lanvia-macos.zip`：通用二进制（Apple 芯片 + Intel）的 `Lanvia.app`，最低 macOS 13，临时签名
- `Lanvia-windows-{amd64,arm64}.exe`：带图标、高 DPI 清单、无控制台窗口（Windows 10/11 自带 WebView2）
- `lanvia-cli-*`：六个平台的命令行版
- `SHA256SUMS.txt`

`scripts/build.sh desktop` 或 `scripts/build.sh cli` 只打其中一部分。图标由 `go run ./tools/genicons` 生成。

## 工作原理

```
 iPhone ─┐  SSE + HTTP                 签名 HTTP 转发
 iPad  ──┼──────────▶  Mac 节点  ◀──────────────────▶  Windows 节点 ◀── 安卓
         │                ▲                                   ▲
         └ 扫码配对        └──── UDP 广播发现 (8687) ──────────┘
```

- **节点**：每台电脑是一个对等节点（Go，网页资源打包进二进制）。桌面客户端把节点跑在同一个进程里，窗口加载它在 localhost 上提供的页面，所以和浏览器里看到的是同一套界面。
- **发现**：每 3 秒在各网卡上广播一个信标，里面带有由配对码派生出的空间 ID。发现同一空间的设备后，用签名请求访问它的 `/api/info` 来确认双方配对码一致。
- **同步**：每条内容有一个随机 ID。节点只转发自己第一次见到的变更，所以网络不需要全连通，也不会形成环路。新节点上线时会拉取对方的历史，删除和清空通过墓碑记录传播。
- **推送**：浏览器通过 Server-Sent Events 接收推送（iOS Safari 上很稳定，每 20 秒发一次保活），回到前台时自动重连。
- **文件**：上传到接收的节点，其他电脑在后台各自备份一份（默认 100 MB 以下，可在设置里调整；每台电脑的文件占用默认不超过 2 GB，超出时只清理副本、不删原件），下载时先找发送方、不在线就找其他有副本的电脑，所以发送方关机也不影响。支持 Range（视频可以拖动进度条）。
- **保留时长**：全局保留时间只对本机生效，过期内容不会再从其他设备同步回来；单条的保留设置会同步到所有设备，同时修改时按时间取新、时间相同按固定规则决胜。
- **编辑与版本**：每次修改生成一个带编辑者和时间的版本，原始内容作为第一个版本保留。版本集合在节点间按 ID 求并集，当前内容取最新的版本，所以多台设备同时编辑也会收敛到同一结果，且不丢任何版本。
- **清单**：按“项”合并，每一项的文字和勾选状态各自按修改时间取新，删除记为墓碑，所以多台设备同时勾选、添加、修改不同的项都不会互相覆盖。清单不受保留时长和数量上限影响，只能手动删除。旧版本设备不认识清单，会直接忽略。
- **标签**：每个标签记录最近一次添加或移除的时间，同步时按标签各自取新（同一时间添加优先），所以多台设备同时增删不同的标签都不会互相覆盖。旧版本设备不认识标签，会忽略它。
- **评论**：每条评论有随机 ID，节点间求并集；删除记为墓碑（取较早的删除时间），所以删除也能传播、不会被同步回来。每条内容最多保留 200 条。旧版本设备不认识评论，经过它们转发时评论会丢，但直接相连的新版本设备之间照常同步。
- **加密**：电脑之间、手机浏览器与电脑之间的请求、推送、转发的内容和文件都用 AES-256-GCM 加密（密钥由配对码派生），按 64 KB 分帧，篡改、截断、调换顺序都会被发现。网页端自带 AES-GCM 实现（局域网 http 页面用不了浏览器的加密接口），与 Go 端的帧格式互通。手机上的图片、视频要先下载并解密再显示，所以视频不能边下边播；超过 256 MB 的文件在手机上明文传输，以免占用同样大的内存。旧版本节点不支持加密时退回明文以保持兼容；设置里可以开启“只允许加密连接”。
- **剪贴板**：macOS 直接调用 NSPasteboard（轮询只读变化计数，几乎不耗电；没有 cgo 时退回 `pbpaste`/`pbcopy`），Windows 直接调用 Win32 API，Linux 用 `wl-clipboard`/`xclip`/`xsel`。复制的文件、被密码管理器标记为敏感的内容不会发送。远端写入的内容会被记住，不会被当成新复制的内容再广播一遍。

## 安全

- 配对码（10 位，约 50 bit）**从不在网络上传输**。两端都从它派生出 HMAC 密钥，每个请求用时间戳 + 随机 nonce + 方法 + 路径 + 查询参数签名，有效期 5 分钟（客户端会先用 `/api/time` 校准时钟）。
- **防重放**：写操作的 nonce 只能用一次，截获的请求原样再发会被拒绝；查询参数在签名里，也不能被改。v0.7 及更早的设备只签时间、方法和路径，仍然接受以保持兼容，但它们发出的请求不受防重放保护。
- 二维码里的配对码放在 `#` 后面，不会发给服务器，读取后立即从地址栏移除。
- 局域网里是 http，浏览器没有 `crypto.subtle`，所以网页端自带了 SHA-256/HMAC 和 AES-256-GCM 的实现（测试里用 node 与 Go 互相加解密验证）。
- 本机仪表盘不用签名，但要求请求来自回环地址、`Host` 是 localhost，并且写操作的 `Origin` 与 Host 一致，以此防 DNS rebinding 和跨站请求。
- 上传的文件返回时带 `Content-Security-Policy: sandbox`，SVG/HTML 一律作为下载附件，不能在本站执行脚本。
- 电脑之间的内容、历史和文件都经过 AES-256-GCM 加密；开启“只允许加密连接”后，也能防止中间人去掉加密。
- **限制**：
  - 网页本身（HTML 和脚本）是通过 http 下发的。同一 Wi-Fi 下只是抓包的人看不到内容；但能篡改流量的人（例如 ARP 欺骗）可以改掉网页里的脚本，进而拿到配对码。
  - 自动化 token 和用它收发的内容是明文。不用时可以在设置里关闭 token 访问，怀疑泄露时可以重新生成。

## 手机上的自动化（可选）

仪表盘“设置 → 自动化”里有一个 API 令牌（由配对码派生，不能反推出配对码；可以重新生成或关闭）。令牌和用它收发的内容是明文传输的。

**iOS 快捷指令**：可以绑定到“轻点背面”或分享菜单。

- 发送剪贴板：`获取剪贴板` → `获取 URL 内容`（POST `http://电脑IP:8686/api/clip`，请求头 `Authorization: Bearer 令牌`，请求体为“文件”，内容选剪贴板）
- 取回最新内容：`获取 URL 内容`（GET `/api/latest`，带同样的请求头）→ `拷贝至剪贴板`

**安卓**：用 HTTP Shortcuts / Tasker 调用相同的接口。

## 网页端的能力边界

- 局域网的 http 页面不能在后台读取剪贴板，所以手机端需要手动粘贴（长按输入框），收到内容后点“复制”即可。电脑上的仪表盘（localhost）是安全上下文，可以一键粘贴。
- 截图或文件可以直接粘贴、拖拽或选择上传，有进度条。
- 会识别验证码和链接，提供“复制验证码”和“打开链接”按钮。
